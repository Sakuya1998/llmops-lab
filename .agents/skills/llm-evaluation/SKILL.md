# 大语言模型评测与发布门禁

## 评测流程

1. 明确模型要完成的任务、目标用户和失败代价。
2. 建立小规模、版本化且许可合规的数据集；学习阶段优先使用合成或公开许可数据。
3. 为每条样本定义输入、参考答案或评分规则、标签和预期行为。
4. 将确定性检查与主观质量评审分开。
5. 固定模型版本、提示词版本、推理参数和评测环境。
6. 对候选版本与基线运行相同数据集，并记录质量、延迟、成本和错误分布。
7. 设置明确的发布门槛；未达到门槛时阻止自动发布，并输出可诊断的失败报告。

## 指标设计

根据任务选择指标，不要把单一分数当作通用质量结论。可以组合：
- 任务特定的准确性或规则检查
- 格式与结构合规率
- 人工评审或经过校准的评审流程
- 延迟、吞吐量、token 用量和成本
- 安全、拒答和隐私相关测试
- 稳定性、重复运行差异与失败案例分类

## 数据与安全

- 不将机密、个人信息或未获授权的数据提交到仓库或外部评测服务。
- 对评测集进行版本管理，并记录来源、许可和变更原因。
- 防止评测集泄漏到提示词调优流程，避免只针对已知测试样本过拟合。
- 使用模型作为评审员时，记录评审模型和提示词版本，并承认其偏差与不确定性。
- 对涉及高风险用途的评测，不应只依赖自动评分。

## 交付要求

提供数据集结构、指标定义、基线与候选版本比较方法、失败样本报告、发布门槛和复现命令。清楚说明评测覆盖范围与未覆盖的风险。
