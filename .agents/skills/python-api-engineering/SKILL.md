# Python API 工程化

## 开始前

1. 阅读根目录 `AGENTS.md` 和相关模块。
2. 检查现有接口契约、测试、依赖与 Git 修改。
3. 明确行为变更、兼容性、错误路径和验收条件；优先最小变更。

## 实现约定

- 使用项目当前支持的 Python 版本与类型标注；依赖统一在 `pyproject.toml` 管理。
- 使用 Pydantic 校验外部输入；不要把未经验证的输入直接交给内部逻辑。
- 保持 HTTP 状态码和错误语义稳定，避免泄露堆栈、密钥或内部配置。
- 为可预期的失败路径编写测试，包括无效输入、资源不存在、边界值和重复请求等适用场景。
- 避免在模块导入时执行昂贵、不可逆或依赖外部服务的操作。
- 对超时、重试、并发、幂等性和限流明确说明策略，不要默认无限重试。
- 日志应结构化、可检索并进行脱敏；不要记录 API Key、授权头、原始提示词或敏感响应内容。
- 不要把当前内存模型登记示例误称为持久化注册中心或真正的推理 API。

## 验证

根据环境执行：

```bash
ruff check .
ruff format --check .
mypy app
pytest
```

若修改格式，先执行 `ruff format .` 再检查差异。记录真实执行结果；依赖缺失或环境限制必须明确说明。

## 解释代码时

按“请求进入 → 校验 → 业务逻辑 → 存储或外部调用 → 响应 / 异常 → 测试”的顺序解释。对每个关键设计说明其收益、代价、故障模式和生产环境需要补齐的部分。
