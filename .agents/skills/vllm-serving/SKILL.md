# vLLM 与模型推理服务

## 先确认约束

开始方案前确认或显式记录：
- 可用硬件：CPU / GPU 型号、显存、数量与驱动环境。
- 模型名称、参数规模、模型格式、许可证和来源。
- 输入与输出 token 长度、并发量、吞吐目标和延迟目标。
- 实验预算、网络限制和数据敏感性。
- 目标运行环境是本地、云主机还是 Kubernetes。

若这些信息缺失，先提供轻量级学习路径或提出一个最关键的问题；不要默认创建付费资源或下载大型模型。

## 学习和实验步骤

1. 解释模型权重、精度 / 量化、KV Cache、上下文长度、批处理和 tensor parallelism。
2. 估算资源需求并标明估算假设；显存使用不仅包括权重，也包括 KV Cache、运行时开销和临时缓冲。
3. 选择许可允许、资源适配的模型和固定版本。
4. 在隔离环境运行服务，设置合理的资源上限与访问边界。
5. 使用固定数据、输入长度、输出长度、并发量和测试时长进行基准测试。
6. 记录吞吐量、TTFT、token 间延迟、错误率、GPU 利用率和显存使用情况。
7. 分析瓶颈后再调整参数；一次尽量只改变一个主要变量。

## 可靠性与安全

- 不将未认证的推理端点暴露到公网。
- 不把真实敏感提示词用于未经批准的实验。
- 不假设不同 vLLM 版本、模型架构和 GPU 的参数完全兼容；必要时查官方文档与 release notes。
- 生产部署需补齐探针、超时、并发控制、请求队列、资源隔离、日志脱敏、监控、容量规划和回滚方案。
- 性能结果必须带环境与测试条件，不得只报告一个脱离上下文的数字。

## 交付

输出实验目的、前置条件、执行步骤、预期指标、结果记录模板、故障排查路径与成本 / 安全风险。
