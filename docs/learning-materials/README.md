# 系统化学习资料

本目录提供与仓库代码配套的中文讲义。它不是让你一次读完的百科全书，而是每天 1–2 小时、围绕代码完成“理解—修改—测试—复盘”的学习材料。

## 学习顺序

| 顺序 | 资料 | 预计时间 | 完成标准 |
|---|---|---:|---|
| 1 | [Python 开发环境与依赖管理](python-environment.md) | 60–90 分钟 | 能解释虚拟环境、依赖声明和 editable install |
| 2 | [HTTP、FastAPI 与 Pydantic](fastapi-and-pydantic.md) | 60–90 分钟 | 能追踪请求从 HTTP 到校验、业务处理和响应的过程 |
| 3 | [pytest 与测试设计](pytest-testing.md) | 60–90 分钟 | 能为正常、异常、边界场景写测试并解释断言 |
| 4 | [Docker、进程与健康探针](docker-healthchecks.md) | 60–90 分钟 | 能构建镜像、用非 root 用户运行，并区分存活与就绪 |

## 推荐学习方法

每次学习只选一个小目标：

1. 先读“为什么需要它”，再看概念和代码。
2. 在仓库中找到对应实现，逐行解释输入、输出和失败路径。
3. 先预测命令或测试结果，再实际运行验证。
4. 自己做一个小改动，不要只复制讲义代码。
5. 将真实结果、错误信息、解决过程写入 `docs/weekly-notes/week-01.md`。

## 给 Codex 的提示词

```text
请遵守仓库 AGENTS.md，并使用 $learning-coach。
今天我学习 docs/learning-materials/README.md 中的第 N 项。
先检查当前代码和 Git 状态，再用运维工程师熟悉的类比解释核心概念。
每次只讲一个概念，给我一个需要自己完成的小任务；先让我尝试，不要直接一次性给出全部答案。
最后依据实际命令结果核对验收标准，并给出可写入周记的复盘问题。
```

## 资料边界

- 讲义中的命令应在本地学习环境执行；涉及云资源、GPU、生产集群或付费服务时，先估算成本并确认授权。
- 版本和工具行为可能变化。遇到不一致时，以仓库锁定的依赖、当前环境输出和官方文档为准。
- 讲义不代表生产环境已具备认证、持久化、高可用或安全加固能力。
