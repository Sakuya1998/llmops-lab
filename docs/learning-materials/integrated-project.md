# 综合项目：可观测、可评测的模型服务平台

## 项目目标

将前面各阶段串成一个能本地复现、可以演示并能解释设计取舍的项目。重点是展示工程能力，不要求一开始运行大模型或购买 GPU。

## 1. 推荐架构

```text
Client / Demo
    |
    v
API / Control Plane
    |  请求校验、认证边界、限流、任务元数据
    v
Model Adapter -----> 本地 mock / 可选真实推理服务
    |
    +----> Structured Logs + Metrics
    |
    +----> Evaluation Runner
                 |
                 +--> Versioned Dataset
                 +--> Baseline / Candidate Comparison
                 +--> Release Gate
```

起步时可用 mock adapter 验证 API、错误处理、指标和评测流水线。真实模型属于可选扩展，需单独评估硬件、许可和成本。

## 2. 功能范围

### API
- 模型部署元数据登记与查询；
- 请求参数和错误契约；
- 请求 ID、超时、并发上限；
- 配置集中管理。

### 模型适配器
- 统一请求/响应接口；
- mock 实现与真实模型实现分离；
- 超时和错误分类；
- 记录模型及参数版本。

### 可观测性
- 请求量、错误率、延迟直方图；
- 输入/输出 token 统计（可获取时）；
- 不记录敏感内容；
- 仪表盘和告警运行手册。

### 评测流水线
- 合成评测数据；
- 基线和候选版本；
- 质量、延迟、成本报告；
- 可配置门禁与失败原因。

### 部署
- Dockerfile 和 CI；
- Kubernetes YAML 作为部署练习；
- requests/limits、探针、非 root 和网络边界；
- 发布检查清单和回滚说明。

## 3. 分阶段里程碑

1. 本地 API 与自动化测试稳定。
2. 抽象模型适配器并提供 mock。
3. 添加结构化日志和 Prometheus 指标。
4. 构建基准评测与回归门禁。
5. 容器化并通过 CI 验证。
6. 编写 Kubernetes 部署清单并静态审查。
7. 在授权且预算明确的环境中可选运行真实模型。
8. 完成故障演练、架构图、风险清单和演示脚本。

## 4. 必须演练的故障

- 模型适配器超时；
- 请求参数无效；
- 下游不可用；
- 并发超过限制；
- 评测结果低于门禁；
- 容器启动慢或探针配置错误；
- 指标标签意外高基数；
- 候选版本错误发布。

每次演练都应记录：注入方式、预期症状、观察信号、缓解步骤、恢复验证和是否需要后续改进。仅在本地或明确授权的测试环境演练。

## 6. 评分标准

| 维度 | 达标表现 |
|---|---|
| 可复现性 | 新环境能按文档安装、运行和测试 |
| 正确性 | 正常、异常和边界行为均有测试 |
| 可观测性 | 关键症状能通过指标/日志定位 |
| 可靠性 | 有超时、限流、降级和恢复策略 |
| 安全性 | 无硬编码密钥，边界和权限明确 |
| 评测能力 | 基线可重跑，退化可触发门禁 |
| 运维能力 | 有容量假设、告警和回滚手册 |
