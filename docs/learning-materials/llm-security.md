# LLM 应用与模型服务安全

## 学习目标

识别传统 Web 风险与 LLM 特有风险，并设计最小可行的防护与测试。安全措施需结合应用场景和数据分类，不存在一条提示词能替代安全架构。

## 1. 主要风险面

- API 身份认证与授权缺失；
- 提示注入与不可信检索内容；
- 敏感数据被发送给外部模型或写入日志；
- 模型输出被直接当作 HTML、SQL、Shell 或工具参数执行；
- 资源消耗失控，例如超长输入、输出或并发；
- 依赖、模型权重和镜像供应链风险；
- 多租户之间的请求、缓存或日志数据泄漏。

## 2. 提示注入与指令边界

用户输入、检索文档和外部工具返回都应视为不可信数据。模型可能无法可靠地区分恶意内容与指令，因此不要仅靠 system prompt 保护秘密或授权工具调用。

应在模型之外执行权限检查、参数校验、工具白名单、资源配额和数据访问控制。模型提出一个操作建议，不等于它已经获得执行权限。

## 3. 工具调用安全

- 工具名和参数采用严格 schema 校验。
- 每个工具有明确的最小权限。
- 高风险操作要求用户确认或独立授权。
- 设定超时、调用次数、预算和输出大小限制。
- 记录必要审计信息，但避免把秘密写入日志。
- 将模型输出视为不可信内容，避免直接拼接进 Shell/SQL/HTML。

## 4. 数据治理

在调用模型前确认数据分类、服务条款、保留政策、区域要求和访问权限。对日志和评测数据实施最小化采集、脱敏、保留期限与访问控制。不要将公司机密或用户隐私发送到未获批准的模型提供商。

## 5. 模型服务保护

- API 认证与授权；
- TLS 与网络隔离；
- 请求体、上下文、输出 token 和并发上限；
- 租户级配额与成本监控；
- 超时、取消与排队限制；
- 模型/提示词版本审计；
- 依赖和模型来源验证。

## 6. 安全测试

建立合成攻击样本，覆盖提示注入、越权工具调用、敏感信息请求、恶意输出格式、超长输入和拒绝行为。评测成功不代表绝对安全；上线后仍需监控、事件响应和持续复测。

## 验收

- 能区分模型提示词与实际授权控制。
- 能解释为什么模型输出不能直接执行。
- 能列出服务上线前的数据、网络、身份和资源控制。
- 能设计一组不含真实敏感数据的安全回归样本。
