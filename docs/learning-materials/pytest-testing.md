# pytest 与测试设计

> 目标：不仅会运行测试，还能用测试描述服务的正确行为。建议用时 60–90 分钟。

## 1. 为什么测试是服务工程的一部分

运维脚本经常通过人工执行来验证结果；服务代码需要在频繁变更时自动证明关键行为没有被破坏。测试也是可执行的接口说明：它记录输入、预期结果和失败边界。

本周先掌握三类测试：

- **正常路径**：合法输入应得到预期响应。
- **异常路径**：无效输入、缺失资源等应返回约定错误。
- **边界路径**：空字符串、长度上限、重复请求、缺失字段等。

## 2. 测试金字塔的实用理解

- 单元测试：验证一个函数或小组件，运行快，失败定位清晰。
- API/集成测试：通过 HTTP 层验证路由、校验和响应契约。
- 端到端测试：验证多个真实组件协作，成本更高。

当前起步项目优先补单元测试与 API 测试，不必一开始就引入复杂测试基础设施。

## 3. pytest 的基本结构

```python
def test_example():
    result = 1 + 1
    assert result == 2
```

pytest 会发现符合命名约定的测试文件与测试函数，并执行断言。断言失败时会展示实际值和预期值，帮助定位问题。

运行：

```bash
pytest
pytest -q
pytest tests/test_api.py -q
pytest -k model -q
```

最后两个示例中的文件名和关键字需要按仓库真实测试名称调整。

## 4. 用 HTTP 客户端测试 API

FastAPI 项目常用测试客户端对应用发起请求，而不是每个测试都启动真实 TCP 服务器。示意代码：

```python
from fastapi.testclient import TestClient
from model_ops_api.main import app

client = TestClient(app)

def test_health():
    response = client.get("/health")
    assert response.status_code == 200
```

导入路径和文件名应以仓库实际结构为准。测试客户端的依赖也应在项目开发依赖中声明。

API 测试建议至少断言：

1. HTTP 状态码；
2. 响应体中的关键字段；
3. 必要的响应头；
4. 失败场景的错误结构；
5. 请求对后续状态产生的影响（如果接口会修改状态）。

只检查“状态码是 200”往往不足以证明业务行为正确。

## 5. 测试数据隔离

如果应用使用内存字典保存模型记录，测试之间可能共享同一个应用对象或全局状态。测试应确保每个用例有干净的数据状态，避免执行顺序影响结果。

可选方式包括：

- 每个测试创建独立的应用或存储实例；
- 使用 fixture 管理测试对象生命周期；
- 在每个测试前后重置共享状态；
- 对未来的数据库依赖，在测试中使用隔离的测试数据库或事务策略。

不要为了让测试通过而无条件清空所有全局变量；应先明确状态由谁创建、谁拥有、何时释放。

## 6. 好测试的特点

- **可重复**：相同代码和环境下结果稳定。
- **独立**：单个测试不依赖其他测试先运行。
- **可读**：测试名称能表达业务行为。
- **有针对性**：失败时能指出具体行为被破坏。
- **不脆弱**：避免断言与业务无关的内部实现细节。

测试不应依赖真实生产凭据、生产数据或不可控的外部网络。涉及外部服务时，应明确使用 mock、fake、测试环境还是契约测试。

## 7. 从需求推导测试用例

例如“删除一个模型记录，成功时返回 204”可以拆成：

| 场景 | 预期行为 |
|---|---|
| 删除存在的记录 | 返回 204；响应不包含 JSON body |
| 删除不存在的记录 | 按项目定义返回 404 或其他明确结果 |
| 删除后再查询 | 记录不再存在 |
| 重复删除 | 按契约明确是否返回 404，或设计成幂等结果 |

这里的“不存在”和“重复删除”行为需要由 API 契约决定，不能只凭个人习惯推断。

## 8. 动手任务

1. 运行现有测试，记录测试数量和结果。
2. 找到健康检查测试与模型创建测试。
3. 为一个无效请求补充测试，验证状态码和错误响应。
4. 为删除接口设计至少三个场景，先写测试再实现接口。
5. 故意把一个预期值改错，观察 pytest 如何报告失败，然后恢复代码。

## 9. 验收标准

- [ ] 能独立运行全部测试和单个测试文件。
- [ ] 能解释单元测试与 API 测试的差别。
- [ ] 至少为一个正常场景、一个错误场景和一个边界场景写测试。
- [ ] 能解释测试隔离的重要性。
- [ ] 不以删除断言或跳过测试作为默认修复方式。
